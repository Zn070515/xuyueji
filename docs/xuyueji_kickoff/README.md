# 续月记 Xuyueji · V1.0 Kickoff 开工包

版本：2026-11-18 / v1.0-kickoff / 文档基线，不是已经完成的软件。

## 一句话

基于 DeepSeek 官方 API、面向公众的完整文本 AI 酒馆：角色卡/世界书/Persona/预设/宏/正则/群聊/分支/长期记忆/数据迁移、跨设备云端存档、支付宝积分制。**云端 PostgreSQL 是权威存储；浏览器 IndexedDB 是缓存和本地草稿；用户始终可导出数据。**

## 已定硬约束

- 新域名 `xuyueji.cn`；浙江个体工商户运营；ICP备案已提交，**未据此认定可公开运营 AI 服务或收费**。
- 新 ECS：阿里云杭州，Ubuntu 24.04，2 vCPU / 2 GiB，40 GiB ESSD Entry，固定 3 Mbps；Caddy + 单体 Fastify + PostgreSQL；禁止在 ECS 上运行大模型或执行生产前端构建。
- 对外 DeepSeek API 由服务端持有密钥；正式服务强制开启官方要求的 `safety_check=high`，不允许用户脚本改写安全边界；不经营 NSFW 内容。
- 用户充值资金与 DeepSeek 预付余额完全独立。支付宝未获正式接入许可前仅用沙箱/假支付，不开放真实充值。
- V1.0 不是功能阉割版；里程碑是**交付顺序**，所有 P0/P1 核心能力均纳入 V1.0 发布门槛。插件/多模态要区分“功能接口完整”与“第三方计费能力已开通”。

## 开发前的 4 项门槛

- 先创建 repo、约束目录、CI、测试容器和 demo 数据；不先写一个庞大的聊天组件。
- 模型价格、支持参数、品牌/协议及支付接口应按**实时官方文档**校验；价格落入带生效期的 tariff 表，不硬编码在前端。
- 任何不确定项登记到 `OPEN_QUESTIONS.md`，不得用猜测补充商业或监管结论。
- 支付截图来自本地运行的**真实页面**（首页、充值页、会话页），不得伪造已开通支付权限。

## 推演总结果

通过架构推演发现 6 条必须跨模块保持的约束：

1. 数据版本与模型生成版本必须一致；生成开始后，另一台设备改设定不能影响该次请求。
2. `generation_run`、最终保留的 `message_node` 和 `wallet_ledger` 是不同对象；不能当作一条记录。
3. 断流、刷新、支付回调重复、客户端重试都不能双重生成/双重扣费。
4. 删除和编辑不能悄悄破坏其他剧情分支；删除必须跨端传播而非被旧缓存复活。
5. 长上下文、省钱缓存、记忆准确性彼此制约，必须展示最终 Prompt 组成与成本预算。
6. 2 GiB ECS 的最小可靠性底线是：限额、背压、异地备份、数据可导出以及有恢复演练。
