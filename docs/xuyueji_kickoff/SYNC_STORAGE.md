# Storage & Sync 协议

## 方案 D 定义

- 云端模式的唯一权威是 PostgreSQL；浏览器 Dexie 保存缓存、草稿、上传中附件元信息与 outbox。
- 客户端离线修改只表示 `pending`，不可以把它显示为“已云端保存”。
- 本地只保留最近使用的会话/角色缓存；老消息按页按需载入，避免 3 Mbps 出网被整库下载占满。
- 用户选择完整备份时从服务端按权限导出全数据；客户端可再保存到设备可见目录。浏览器默认不能自动写入 `~/.xuyueji`。

## 协议草案

`GET /api/sync?cursor=<opaque>` → `{changes, nextCursor, hasMore, serverTime}`，按用户分区、升序且可重复拉取。
`POST /api/mutations` → `{accepted:[{opId,newRev}], conflicts:[...], rejected:[...]}`。每个操作有 `opId`（幂等）、`entityId`、`expectedRev`、`action`、`payload`；服务端在同一短事务中写实体和同步日志。
`GET /api/conversations/:id/messages?before=<cursor>&limit=...` → 分页消息图，不能只返回一维数组丢失分支信息。

## 三种冲突

- 设置字段：白名单字段 LWW 可以接受，服务端提供最终 revision。
- 角色/世界书/预设：CAS 失败 → 409、保留用户本地草稿、显示差异、复制为新版本/手工合并，不静默覆盖。
- 消息：同一分支竞态冲突 → 新分支或明确 409；已确认消息不可静默重写。

## 多设备离线/删除

- 软删除 tombstone + 同步日志，旧设备回来后必须先消费删除。
- 同步 cursor 太旧或服务端日志已裁剪：返回 `resync_required`，重建缓存并保留待提交草稿以待核对，防止“僵尸记录”复活。
- 本地缓存既不包括支付凭证也不保存 DeepSeek API Key；余额展示从服务端拉取。
- 设备注销/退出应清除敏感会话缓存；跨用户切换不能读取上一账号缓存。

## 备份与可移植格式

导出 ZIP 包含 `manifest.json`（schema_version、exported_at、hashes、features）、角色、Persona、世界书、预设、正则、聊天消息图、记忆及附件。费用/订单另行提供个人账单下载，不导入覆盖余额。

- 备份需流式打包或分片，避免 VPS 内存峰值暴涨；压缩炸弹、路径遍历、重复附件引用均检查。
- 必须提供数据导出准确性证明：计数、哈希、缺失附件清单；兼容导入前 dry-run + 显示冲突处理选项。
- 真实文件夹增强：Chrome/Edge 等支持环境由用户选择/授权目录，不承诺跨平台支持；默认 Web 模式不依赖它。

## 容灾策略

数据库逻辑备份定期生成，备份加密后上传 ECS 之外的存储（可使用已有受控设备或合规远端）；至少保留数代；明确 RPO/RTO 目标后用演练验证，不能把“执行过 pg_dump”当作已经可恢复。
对已购平台积分的财务数据单独设置更高的备份核验频率；恢复时要先处理外部支付回调补账，防止回滚后重复入账。
